The challenge

Make a campus golf cart drive itself — affordably

Campus transport relies on human drivers, while commercial autonomous shuttles cost USD 150,000–350,000. The project retrofitted an existing Club Car Precedent i2 Excel with five removable subsystems — perception, model predictive control (MPC), steering, braking and throttle — for about BHD 1,800 per vehicle, with no permanent modifications.

For the perception team, the challenge was campus roads: shadows, curves, crosswalks, night and rain. The system had to keep producing a stable trajectory for the controller even when individual camera frames failed, and spot obstacles in the cart's lane.

My role

What I did (Team A — Perception)

  • Built a classical lane-detection baseline first (HSV, Canny, Hough), then showed where it fails: night, rain, curves and worn markings.
  • Implemented machine-learning lane detection with HybridNets (EfficientNet-B3 backbone), using its drivable-area output for stability.
  • Designed a 3-level fallback chain (sliding window, DBSCAN clustering, edge pixels) so a lane estimate is always available.
  • Generated the trajectory sent to the controller: lateral offset, curvature and a steering estimate from a polynomial centreline fit.
  • Integrated YOLOv8n object detection with Intel RealSense depth to flag in-lane hazards and stop signs.
  • Validated the pipeline in CARLA simulation together with the MPC team.
Method

From camera frame to steering command

  1. Fit into the whole system

    Perception passes only three filtered values to the MPC controller every 0.1 s cycle: lateral offset, curvature and an obstacle flag. Curvature lets the controller steer into a curve before any error builds up.

  2. Detect the lane with machine learning

    HybridNets segments each frame into drivable area and lane lines. A sliding-window search finds the boundaries, with DBSCAN clustering and edge pixels as fallbacks, so the pipeline never returns nothing.

  3. Stabilise the output

    A three-stage filter checks lane width (2.5–5.5 m), rejects impossible values, and smooths the rest with an exponential moving average tuned to the cart's speed. If a frame fails, the last valid values are held.

  4. Detect obstacles and test in simulation

    YOLOv8n detects vehicles, pedestrians and stop signs; the depth camera gives their distance. An object is a hazard only if it is inside the drivable lane and close enough. The full loop was tested in CARLA before touching the real cart.

Results

  • Stable lane detection in 5 conditions: daytime, night, rain, multi-lane intersection and curved road.
  • Zero pipeline failures producing unsafe input to the controller across 322 evaluated frames.
  • Whole system: zero lane departures in CARLA at 0.5, 1.0 and 1.5 m/s, and 8.21 cm mean tracking error on a 117.5 m curved path.
  • 6 of 7 project objectives achieved, and the Best Community Project Award at the Bahrain Polytechnic Engineering Expo 2026.

Lessons learned

  • The handling around a model — filtering, fallbacks, freeze-on-failure — matters as much as the model itself.
  • Simulation first: a bad setting seen in CARLA takes minutes to fix; on the real vehicle it could damage it.
  • Next steps: fine-tune HybridNets on local campus images and run it on a Jetson for 20–30 FPS.
